01Fundamentos de confianza

Confidencialidad: TLS cifra los datos en tránsito. Integridad: hashes y firmas detectan cambios. Autenticación: el certificado X.509 vincula una clave pública con una identidad, según la cadena de confianza.

02Identidad y certificados

Una identidad de firma requiere un par de claves y un certificado. Un certificado autofirmado sirve para pruebas, pero navegadores y sistemas no lo consideran confiable por defecto. Un archivo PFX/PKCS#12 puede contener la clave privada: protégelo con contraseña y nunca lo publiques ni lo envíes al navegador.

03Despliegue de HTTPS

En un servidor real, configura un certificado válido para tu dominio, la cadena completa de la CA y el listener TLS del puerto 443 (por ejemplo, Apache con mod_ssl o Nginx con ssl_certificate). Redirige HTTP a HTTPS y renueva el certificado antes de su vencimiento. El indicador de arriba informa el protocolo de esta página; no inspecciona el certificado ni sustituye la validación del navegador.

04Firma y verificación de archivos

Usa la pestaña Validar PDF para aceptar únicamente archivos PDF con firma digital íntegra y certificado de confianza. Para firmar un ejecutable de Windows con Authenticode y sello de tiempo necesitas herramientas como osslsigncode, un certificado de firma de código emitido por una CA y una TSA.

05Evaluación

  • Transporte: abre el sitio publicado con https:// y revisa el certificado en el navegador.
  • Integridad: valida un PDF firmado y luego modifica una copia; la comprobación debe fallar.
  • Identidad: el certificado del firmante debe encadenar a una CA de confianza del sistema.
  • Sello de tiempo: valida el token TSA de una firma Authenticode; la hora del equipo o de esta demo no es un sello de tiempo confiable.

La validación de certificados PDF requiere el servidor local de esta aplicación. No se aceptan PDFs sin firma digital, con firma alterada o con certificado no confiable.

Validar un PDF certificado

Solo se marcará como válido un PDF con al menos una firma digital íntegra y un certificado que encadene a una CA de confianza.

Resultado de validación

La comprobación se realiza en el servidor local usando las CA confiables del sistema. Los certificados autofirmados o desconocidos no se aceptan. La revocación en línea (OCSP/CRL) no se consulta; los PDFs se procesan solo en este equipo.

Codifica o decodifica texto

Codificar no cifra ni protege el texto: Base64, URL, hexadecimal y binario se pueden revertir sin contraseña.

Calcula la huella digital del texto

Un hash es irreversible: sirve para comparar integridad, pero no para recuperar el texto original. Para contraseñas de usuarios se debe usar un algoritmo específico como Argon2id, bcrypt o scrypt.

Cifra o descifra con una contraseña

El cifrado usa AES-256-GCM y una clave derivada con PBKDF2-SHA-256. El procesamiento ocurre en tu navegador; el paquete incluye los datos necesarios para descifrarlo. Guarda tu contraseña: no se puede recuperar si la pierdes.

Los archivos y textos se procesan localmente en este equipo; no se envían a servicios externos.
